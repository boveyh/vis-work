# Layout Lab 视觉层次、学习页空间与测验设计

日期：2026-09-16  
状态：用户已确认，等待实施计划  
适用项目：Layout Lab 纯前端双语布局课程

## 1. 目标

本轮更新解决三个问题：

1. 整站颜色寡淡，页面层次和品牌记忆不足。
2. 学习页主要内容集中在左侧，右侧空间利用不足。
3. 当前考核选项看起来像功能按钮，完成标准的最后一项不易理解，课程也缺少章末和阶段性检验。

继续保留纯前端、Hash 路由、中英文切换、主题切换和浏览器本地进度。不开设账号、服务端判题、自然语言语义判定或云同步。

## 2. 视觉方向

采用用户选定的 A 方案“编辑式橙蓝”。

### 2.1 色彩职责

- 深蓝：顶栏、章节导航、主要结构和高权重文字。
- 橙色：当前步骤、主要操作、选中状态和品牌识别。
- 米白：页面与阅读区底色，降低纯白页面的空泛感。
- 蓝灰：教学板、次要信息和结构分区。
- 绿色：仅用于答题正确和通过状态。
- 红色：仅用于错误与需要修正的状态。

橙色仍是唯一主要强调色。阶段差异只使用低饱和浅色底、阶段编号和辅助线，不为每个阶段建立互相竞争的主色。

### 2.2 层次规则

- 页面背景、阅读面板和教学板至少形成三个可辨认层级。
- 边框与浅阴影只用于分离工作区，不为每段内容套卡片。
- 当前章节、当前步骤和当前任务必须一眼可见。
- 交互控件使用同一圆角、焦点环和选中样式。
- 动效只用于教学板状态变化、答题反馈和进度更新，并兼容减少动态效果设置。

## 3. 学习页布局

### 3.1 桌面端

学习页采用三栏工作台：

```text
章节导航约 220px | 学习正文 minmax(560px, 1fr) | 同步教学板约 360px
```

- 左栏：课程阶段、章节列表、当前位置和完成状态。
- 中栏：问题情境、预测、原理、操作说明、即时选择题和章末小测入口。
- 右栏：与当前步骤同步的布局示意、关键 CSS、变化解释和目标条件。
- 右栏在可用高度内粘性定位；到达章末测验区域前恢复正常文档流，不能遮挡页尾内容。
- 页面最大宽度约 1440px。窄桌面优先压缩正文与教学板间距，不隐藏教学信息。

### 3.2 同步规则

- 阅读预测题时，教学板显示初始状态和待观察目标。
- 阅读概念步骤时，教学板突出对应的容器、轴线、尺寸或定位参照。
- 操作参数后，教学板立即更新布局、相关 CSS 和一句因果解释。
- 进入即时题时，教学板保留学生刚完成的最终状态，作为答题依据。
- 正文中不再重复渲染第二套完整 Playground。

### 3.3 响应式

- 中等宽度下，左栏收为紧凑章节导航，正文和教学板保持双栏。
- 小屏改为单栏，顺序为“任务说明、教学板、原理与操作、即时题”。
- 章节导航收进顶部目录，不占据固定侧栏。
- 代码块只在自身范围横向滚动，选择题和主要按钮保持全宽可点击。

## 4. 即时选择题

每章当前的最后一道题继续保留，用于检查学生是否能解释刚才的操作结果。

### 4.1 表达方式

- 明确标注“即时检查 · 单选题”。
- 题干直接说明要判断的规则或结果。
- 选项采用标准单选结构，不能继续呈现为三个并列功能按钮。
- 选择后显示当前选中状态；提交前允许更改。
- 提交错误后给出与错误原因相关的提示，不直接公布答案。
- 提交正确后，将完成标准第三项标记为“已正确解释布局变化”。

### 4.2 完成标准

章节学习过程仍记录三项证据：

1. 已完成预测。
2. 教学板达到目标布局条件。
3. 即时选择题回答正确。

按钮旁明确指出尚缺哪一项，避免只显示不可用按钮。

## 5. 章末小测

### 5.1 题量与难度

- 每章 3 至 5 道单选题，默认 4 道。
- 以概念识别、规则与结果对应、常见错误判断和简单场景应用为主。
- 不设置文字陷阱、偏门语法或需要背诵的细枝末节。
- 首版使用固定题目和固定选项，不随机抽题。

### 5.2 交互流程

1. 学生完成本章三项学习证据后，章末区域开放“开始章末小测”。
2. 小测直接显示在章节末尾，避免完成一章后立即跳页。
3. 所有题目选择完毕后才能提交。
4. 错题显示提示和知识点定位，但不标出正确选项。
5. 学生只需修改错题，已经正确的题目保持正确状态。
6. 全部答对后记录“章末小测通过”，并显示下一章或阶段测试入口。

## 6. 阶段综合测试

### 6.1 开放条件与题量

- 每个阶段所属章节的章末小测全部通过后开放。
- 每个阶段约 10 道单选题。
- 内容覆盖该阶段全部章节，并包含少量跨章节的简单综合判断。
- 难度保持基础，不使用超出课程正文的知识。

### 6.2 页面与反馈

- 阶段综合测试使用独立页面，避免十道题挤在章节正文中。
- 页面顶部显示所属阶段、题量、当前完成数量和通过条件。
- 首次提交后，正确题锁定或保持完成状态；错题允许继续修改。
- 每道错题提供一条分层提示：先指出应回顾的概念，再提示观察对象或判断方向。
- 不直接公布正确答案；全部答对后记录“阶段测试通过”。
- 通过页面提供下一阶段入口，并允许以后重新练习，但重做不清除已有通过记录。

## 7. 题目数据与判定

题目采用结构化静态数据，由浏览器直接判定：

```ts
type QuizQuestion = {
  id: string;
  prompt: LocalizedCopy;
  options: LocalizedCopy[];
  answer: number;
  hint: LocalizedCopy;
  concept: LocalizedCopy;
};

type Quiz = {
  id: string;
  kind: "chapter" | "stage";
  lessonIds: string[];
  questions: QuizQuestion[];
};
```

判定只比较结构化选项索引，不检验自由文本，也不执行学生输入的代码或 JavaScript。

## 8. 进度状态

进度至少区分以下状态：

```ts
type LearningProgress = {
  lessonEvidence: Record<string, {
    predicted: boolean;
    practiced: boolean;
    instantCheckPassed: boolean;
  }>;
  chapterQuizPassed: string[];
  stageTestPassed: string[];
};
```

- 学习证据完成不等于章末小测通过。
- 章末小测通过不等于阶段测试通过。
- 首页和课程导航分别显示阅读学习、小测和阶段测试状态。
- 数据继续保存在 `localStorage`，并对现有章节完成数据进行兼容迁移。
- 本地存储不可用时仍可答题，但明确提示本次进度不会保存。

## 9. 组件边界

在沿用现有 React 架构的前提下，新增或调整以下职责：

- `LearningLessonPage`：组织三栏工作台与章节流程。
- `SectionActivity`：保留预测、操作和即时选择题，不再承担完整章末小测。
- `LessonBoard`：在右栏同步展示当前概念、布局状态和因果解释。
- `QuizQuestionView`：统一渲染单选题、选中状态和错误提示。
- `ChapterQuiz`：在章节末管理 3 至 5 道题与通过状态。
- `StageTestPage`：管理约 10 道综合题、错题重答和阶段通过状态。
- `ProgressStore`：读取、迁移和保存三层进度。

优先复用现有数据、按钮、反馈和进度逻辑，不为本轮更新引入新的 UI 框架或状态管理依赖。

## 10. 异常与可访问性

- 题目数据缺失或答案索引越界时，不允许记录通过，并显示可恢复的错误提示。
- 未答完全部题目时，提交按钮说明还剩多少题。
- 所有选项支持键盘聚焦和选择，焦点状态清晰可见。
- 正确与错误不能只依赖颜色，同时显示图标和文字。
- 中英文题目共享同一个题目 ID 和答案索引，切换语言不清空作答。
- 刷新页面后恢复未完成的选择；版本变化导致题目不兼容时，只清除对应测验草稿，不删除已经通过的历史记录。

## 11. 验收标准

### 11.1 视觉与布局

- 整站能明确识别深蓝结构、米白阅读面、橙色交互重点和蓝灰教学板。
- 桌面学习页右侧不存在无职责的大块空白。
- 1024px、1280px 和 1440px 下三栏不溢出，360px 和 768px 下内容顺序正确。
- 教学板与正文状态一致，不出现重复的完整演示组件。

### 11.2 即时题

- 选项能被识别为单选题，而非页面功能按钮。
- 错误答案有针对性提示，正确答案能完成第三项学习证据。
- 页面明确指出尚未满足的完成条件。

### 11.3 章末与阶段测试

- 八章各有 3 至 5 道章末小测题，默认 4 道。
- 四个阶段各有约 10 道综合测试题。
- 错题不会直接显示答案，修改后可重新提交。
- 只有全部答对才能记录通过。
- 刷新、切换语言和切换主题后，作答与通过状态保持一致。

### 11.4 构建与回归

- TypeScript 构建和 Vite 生产构建通过。
- Hash 路由可直接访问阶段测试页面并正常刷新。
- 旧进度能迁移，现有课程、实验室、主题和双语功能不回退。
- 不新增服务端、数据库或运行时网络依赖。

## 12. 实施顺序

1. 建立视觉 token 和三栏学习页骨架。
2. 将教学演示收敛到同步右栏，消除重复和空白。
3. 把即时检查改为明确的单选题及三项完成提示。
4. 增加题目数据结构、统一题目组件和章末小测。
5. 增加阶段综合测试页面、路由和进度状态。
6. 补齐八章章末题与四个阶段综合题。
7. 完成响应式、键盘操作、本地进度迁移和构建回归测试。

## 13. 明确不做

- 不用自由文本回答代替可判定的选择题。
- 不引入 AI 判题、模糊语义匹配或关键词打分。
- 不随机抽题，不制作计时、排名、连续签到或惩罚机制。
- 不引入新的组件库、状态库或服务端。
- 不把视觉增强变成大面积渐变、玻璃效果或无教学意义的动画。
