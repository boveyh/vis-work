# Layout Lab 学习体验与可视化演示优化方案

日期：2026-09-14  
状态：待用户复核  
替代方案：本文件更新并替代 `2026-09-11-layout-learning-system-design.md` 中的首页、章节学习页、演示系统、进度与视觉设计。

## 1. 目标与设计判断

Layout Lab 继续作为可部署到 GitHub Pages 的纯前端双语课程，但产品重心从“展示课程设计能力的宣传页”调整为“学生打开后可以直接继续学习的课程工作台”。

目标用户是刚开始系统学习 HTML 与 CSS 布局的学生。他们需要明确的学习顺序、可观察的布局变化、短而连续的练习以及及时反馈。视觉设计首先服务于理解、定位和操作。

新的设计参数：

- `DESIGN_VARIANCE: 3`：稳定、规则、容易扫描。
- `MOTION_INTENSITY: 2`：动效只解释位置、尺寸与状态变化。
- `VISUAL_DENSITY: 7`：首屏能看到当前任务和课程路径，减少宣传页式留白。
- 整站继续使用浅色与深色主题、橙色单一强调色和 Phosphor 图标。

成功标准：

- 返回网站的学生在首屏内看到上次位置和唯一的继续入口。
- 学生始终知道“所在章节、当前小节、当前步骤、下一步动作”。
- 演示不依赖真实产品文案，CSS 属性造成的几何变化可以被直接识别。
- 每个知识点形成“预测、观察、解释、练习、反馈”的闭环。
- 完成状态主要来自练习结果，而不是手动点击“已完成”。
- 所有核心功能只使用静态课程数据、浏览器状态和客户端校验。

## 2. 保留、调整与移除

### 2.1 保留

- 八章、四阶段的课程骨架。
- Hash 路由、中英文切换、主题切换和 GitHub Pages 部署方式。
- 左侧课程导航、中间学习内容、右侧实验区的桌面工作台基础。
- `localStorage` 本地保存进度和偏好。
- 现有橙色品牌强调色、低装饰的正文与代码风格。

### 2.2 调整

- 首页从营销首屏改为学习仪表盘。
- 整章“理论 / 代码 / 演示”标签改为按学习步骤连续推进。
- 通用 Playground 改为面向概念的可视化教学板。
- 章节完成进度下沉到小节和练习。
- 每章从四段概述扩展为 4 至 6 个可学习、可练习的小节。

### 2.3 移除或合并

- 移除首页大型 Flexbox Playground。
- 合并首页课程阶段与完整章节列表的重复表达。
- 合并课程地图与首页重复的课程入口职责。
- 合并章节右栏 Playground 与“演示”标签中的重复实例。
- 合并独立挑战页和第八章综合挑战的重复内容。
- 删除无教学意义的模拟站点文案、装饰指标、复杂阴影和大面积留白。

## 3. 信息架构

建议保留现有路由，调整页面职责：

```text
/#/zh/                         学习首页：继续学习、进度、课程路径
/#/zh/course                  完整课程地图与知识点索引
/#/zh/lesson/:lessonId        章节学习工作台
/#/zh/challenge               综合挑战入口，可重定向至第八章挑战步骤
/#/zh/about                   学习方式、进度存储、课程说明
```

顶部主导航收敛为：

```text
Layout Lab | 学习路径 | 实验室 | 综合挑战 | 进度 | 中/EN | 主题
```

“实验室”是学生自由调参数的独立入口；章节里的教学演示带有具体任务和反馈。两者复用同一个渲染引擎，但承担不同用途。

## 4. 首页：从宣传页改为学习仪表盘

### 4.1 首屏

顶栏高度约 56px。首屏不再使用大号宣传标题和双栏演示，只显示一个主要学习状态卡：

```text
Layout Lab
前端布局学习路径                         已完成 7 / 42 个小节

继续学习
03 Flexbox · 2.2 主轴与交叉轴
下一步：预测 justify-content 的排列结果
预计 8 分钟

[继续学习]
```

首次访问没有历史记录时，内容切换为课程起点和简短的“适合谁、学完能做什么”。主操作始终只有一个。

### 4.2 课程路径

首屏下方直接呈现四个阶段和八章。使用紧凑的列表或两列分组，不再使用大面积卡片：

- 阶段目标；
- 章节名称；
- 小节完成数量；
- 预计用时；
- 当前、完成、待学习状态；
- 必要的先修关系。

章节行点击后进入最近未完成的小节。完整知识点索引继续放在课程地图页，首页只承担继续学习和查看路径。

### 4.3 次要内容

学习方法、课程特点、数据存储说明和 GitHub 链接放在路径之后。宣传口号最多保留一句，不再占据独立大区块。

## 5. 章节页：连续学习步骤

### 5.1 桌面布局

```text
章节与小节目录  |  当前学习步骤                   |  可视化教学板
220 至 240px    |  680 至 760px                  |  360 至 420px
```

- 左栏显示阶段、章节、小节、完成状态和当前位置。
- 中栏按顺序展示当前小节的学习步骤。
- 右栏只保留一个教学板，并随当前小节同步内容。
- 顶部显示面包屑、学习目标、预计时间和小节进度。

### 5.2 单个小节的学习闭环

每个知识点统一采用：

1. **问题情境**：用一句具体目标说明要解决什么。
2. **先做预测**：学生选择或指出可能的变化。
3. **操作观察**：只提供当前概念需要的 1 至 3 个控件。
4. **机制解释**：说明属性如何改变尺寸、轴线或位置。
5. **错误对照**：展示一个常见错误及其原因。
6. **微练习**：修改参数或补全一条 CSS 规则。
7. **即时反馈**：指出正确部分、错误原因和下一步提示。
8. **一句总结**：要求学生从选项中识别本节核心规则。

整章不再通过“理论 / 代码 / 演示”标签拆开。完整 HTML、完整 CSS、属性速查和补充解释使用折叠区渐进披露。

### 5.3 移动端

- 左侧目录变为顶部可横向滚动的小节导航或目录抽屉。
- 学习内容与教学板按“任务、演示、解释、练习”的顺序单栏排列。
- 教学板保持在正文流内，不使用重复组件实例。
- 代码块只在自身范围内横向滚动。

## 6. 可视化教学板

### 6.1 设计原则

教学板采用抽象布局示意，而不是缩小版真实网站。统一语言包括：

- 容器：清晰实线边框；
- 项目：标记为 A、B、C 的简单几何块；
- 当前受影响对象：橙色；
- 未受影响对象：中性灰；
- 主轴和交叉轴：带方向箭头的辅助线；
- padding：容器内部浅色区域；
- margin：容器外部虚线区域；
- gap：项目之间直接标注距离；
- 尺寸：在对应边缘显示宽度和高度；
- 定位参照：从元素到参照容器的辅助线；
- 层叠：使用轻微透明度和明确的层级编号。

不使用渐变、装饰插图、产品名称、大段模拟文案和无关指标。动画只平滑过渡 `transform`、尺寸和透明度，并支持减少动态效果设置。

### 6.2 固定结构

```text
┌ 当前任务：观察项目如何沿主轴排列 ─────────────┐
│                                               │
│ 主轴 →                                        │
│ ┌───────────────────────────────────────────┐ │
│ │        A          B          C            │ │
│ └───────────────────────────────────────────┘ │
│                                    ↑ 交叉轴   │
├───────────────────────────────────────────────┤
│ flex-direction   [ row ▼ ]                    │
│ justify-content  [ center ▼ ]                 │
│ gap               ─────●──── 24px             │
├───────────────────────────────────────────────┤
│ 变化：三个项目沿主轴居中，项目间距为 24px      │
│ [重置]                              [查看 CSS] │
└───────────────────────────────────────────────┘
```

教学板由五部分构成：任务、示意图、控件、变化解释、次要操作。生成 CSS 默认折叠，避免学生先关注语法而忽略现象。

### 6.3 交互规则

- 每个小节最多三个控件。
- 控件标签使用真实 CSS 属性名，旁边给出简短中文含义。
- 每次变化都生成一句因果解释，例如“主轴从水平改为垂直，因此 A、B、C 从上到下排列”。
- 可选的预测题必须在操作前出现；提交后再开放控件。
- 重置恢复当前教学任务的起始状态。
- “查看 CSS”只展示与当前变化有关的规则并高亮变更行。
- 教学状态与自由实验状态分离，避免学生在章节之间继承无关参数。

## 7. 八章演示方案

| 章节 | 教学板示意 | 核心操作 | 直接反馈 |
| --- | --- | --- | --- |
| 页面如何形成 | Header、Main、Aside、Footer 四个结构块 | 切换 block / inline，显示或隐藏语义边界 | 指出元素是否独占一行及页面结构角色 |
| 盒模型与文档流 | content、padding、border、margin 四层剖面 | 调整 width、padding、box-sizing | 同时显示声明宽度与最终占用宽度 |
| Flexbox | A、B、C 加主轴与交叉轴 | direction、justify、gap | 描述轴线变化、空间分配与项目间距 |
| 定位与层叠 | 父容器、角标、三个重叠方块 | position、定位参照、z-index | 画出参照线并显示当前层级顺序 |
| CSS Grid | 编号网格线、轨道与 A 至 F 单元格 | columns、gap、auto-fit / 固定列 | 标出行列数量、轨道宽度和换行结果 |
| 响应式布局 | 可拖动宽度的小浏览器框和断点尺 | viewport、布局模式、容器宽度 | 显示当前宽度、命中规则和结构变化 |
| 常见页面模式 | 单栏、双栏、侧栏、卡片流的纯线框 | 选择内容结构与布局工具 | 解释为什么选择文档流、Flex 或 Grid |
| 综合布局挑战 | 导航、主内容、侧栏、页脚目标轮廓 | 分步骤选择布局方式和关键参数 | 对照目标轮廓检查区域、溢出和三端适配 |

真实应用示例放在每个知识点结尾，使用一张小型静态线框说明“这种规则常用于哪里”，不进入 Playground，也不与抽象示意图切换。

## 8. 内容扩充方案

八章数量维持不变，优先增加纵向深度。每章拆为 4 至 6 个小节，每个小节只教一个清晰概念。

内容层级：

```text
阶段目标
  章节目标
    小节问题
      直觉规则
      可视化实验
      关键代码
      错误对照
      微练习
      本节总结
  章节综合练习
阶段项目
```

内容写作要求：

- 每段解释回答“哪个属性改变了什么几何关系”。
- 代码示例先显示最小规则，再提供完整代码。
- 每个概念至少包含一个错误结果和原因。
- 相邻练习改变内容或约束，避免机械重复同一答案。
- 初学阶段提供完整示例，后续逐步移除提示。
- 每章结束加入 2 至 4 道检索题和一个组合任务。

## 9. 进度与引导

### 9.1 进度层级

```ts
type SectionProgress = {
  lessonId: string;
  sectionId: string;
  predictionAnswered: boolean;
  experimentUsed: boolean;
  practicePassed: boolean;
  attempts: number;
  completedAt?: string;
};
```

显示状态：未开始、学习中、练习通过、需要复习。课程总进度按通过的知识点计算，章节页的阅读行为不直接等于掌握。

### 9.2 下一步推荐

纯前端按固定规则生成：

1. 有未完成的当前小节时继续该小节；
2. 当前小节练习失败时进入复习步骤；
3. 当前章完成后进入章末练习；
4. 阶段完成后进入阶段项目；
5. 没有历史记录时进入第一章第一节。

不引入账号、服务端推荐或云同步。

## 10. 组件与数据边界

建议在实施时把当前较集中的 `App.tsx` 和 `data.ts` 按职责拆分，但不进行与学习体验无关的重构。

主要组件：

- `LearningDashboard`：首页当前任务和课程路径。
- `CourseOutline`：章节、小节与状态导航。
- `LearningStep`：渲染问题、预测、解释、练习和总结。
- `ConceptBoard`：渲染统一的抽象布局示意图。
- `PropertyControls`：根据小节配置生成最多三个控件。
- `ChangeExplanation`：把参数变化转为因果解释。
- `FocusedCode`：展示当前相关 CSS 和变更高亮。
- `PracticeCheck`：按白名单规则校验答案并给出提示。
- `ProgressStore`：读写和迁移本地学习状态。

建议数据契约：

```ts
type LessonSection = {
  id: string;
  title: LocalizedText;
  objective: LocalizedText;
  situation: LocalizedText;
  prediction?: PredictionConfig;
  board: BoardConfig;
  explanation: LocalizedText;
  mistake: MistakeConfig;
  practice: PracticeConfig;
  takeaway: LocalizedText;
};
```

`BoardConfig` 只描述容器、项目、轴线、尺寸、层级和允许的控件。组件负责渲染，课程数据不包含任意 HTML 或 JavaScript。

## 11. 客户端校验与安全边界

- 只允许预定义 CSS 属性和值进入演示渲染器。
- 文本补全练习解析为白名单声明，不执行用户 JavaScript。
- 选择题、参数题和布局状态题优先使用结构化答案。
- 自由代码挑战在隔离的 `iframe` 或受控样式作用域中渲染。
- 学生错误样式不得影响课程外壳。
- 校验失败时区分语法错误、属性错误、值错误和布局结果不匹配。

## 12. 异常与降级

- `localStorage` 不可用：课程正常学习，显示“本次进度不会保存”。
- 历史进度格式过期：迁移可识别字段，无法迁移时保留备份并从当前章节开始。
- 演示配置错误：显示本节静态示意和重试入口。
- 复制失败：选中代码并提示手动复制。
- 减少动态效果：立即切换布局状态，保留箭头、尺寸和文字解释。
- 小屏无法并排：教学板放入正文步骤，不丢失任何操作。
- 翻译缺失：界面回退中文，构建阶段报告缺失字段。

## 13. 验收与测试

### 13.1 学习路径

- 首次访问一键进入第一章第一节。
- 返回访问一键恢复到最后未完成步骤。
- 首页不存在多个相同意图的主要按钮。
- 学生能从任何章节明确返回课程路径或进入下一小节。

### 13.2 教学板

- 八类教学板的几何变化与生成 CSS 一致。
- 每个小节的控件不超过三个。
- 主轴、交叉轴、间距、尺寸和定位参照标记不会遮挡主要内容。
- 360px、768px、1024px 和 1440px 下均可操作。
- 键盘可完成预测、控件调整、重置、查看代码和提交练习。
- 减少动态效果后仍能理解变化。

### 13.3 进度与反馈

- 练习通过后才记录对应知识点完成。
- 刷新、切换语言和切换主题后保持学习位置。
- 错误答案提供原因和分级提示，不直接只显示完整答案。
- 旧版 `layout-lab-progress` 可以迁移到新的小节进度结构。

### 13.4 内容与视觉

- 每章有 4 至 6 个小节，每节包含问题、示意、解释、错误和练习。
- 正文默认 16px，章节标题约 30 至 34px，顶栏约 56px。
- 整站只使用一个强调色和统一圆角规则。
- 首页首屏能同时看到当前任务与课程路径起点。
- 装饰动画、模拟产品文案和与概念无关的视觉元素为零。

## 14. 实施优先级

### 第一阶段：结构与去重

1. 首页改为学习仪表盘。
2. 继续学习入口根据真实进度计算。
3. 章节页改为连续学习步骤。
4. 移除重复 Playground 和重复挑战入口。

### 第二阶段：教学板基础

1. 建立统一的 `ConceptBoard` 数据契约。
2. 完成盒模型、Flexbox、Grid 三个核心教学板。
3. 加入变化解释、聚焦代码与减少动态效果支持。

### 第三阶段：学习闭环

1. 加入预测题和微练习。
2. 建立客户端校验和分级提示。
3. 把进度从章节完成迁移为知识点掌握。

### 第四阶段：内容扩充

1. 将八章拆成完整小节。
2. 补齐错误对照、变式练习和章末检索题。
3. 完成定位、响应式、常见模式和综合挑战教学板。

### 第五阶段：视觉与质量验收

1. 压缩字号、间距、卡片和顶栏尺寸。
2. 验证移动端、键盘操作、对比度和减少动态效果。
3. 验证 Hash 路由、GitHub Pages、双语内容和本地进度迁移。

- Nielsen Norman Group 渐进披露：优先显示当前任务必需内容，详细资料按需展开。<https://www.nngroup.com/articles/progressive-disclosure/>

## 16. 明确不做

- 不添加登录、数据库、云同步、排行榜、评论或社交功能。
- 不引入通用在线 IDE 或任意 JavaScript 执行器。
- 不为增强艺术感添加图片、渐变、玻璃效果、视差或持续动画。
- 不增加大量章节来制造内容丰富感，先把现有八章做深。
- 不使用复杂推荐算法，下一步学习路径由透明的本地规则决定。
